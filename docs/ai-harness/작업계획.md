# AI Harness IDE — 작업 계획서

- 작성일: 2026-04-20
- 작성자: 이태환
- 상태: 검토 대기

---

## 1. 요약

VS Code 최신 버전(1.117)을 fork하여, Void 프로젝트의 AI 기능을 이식하고 우리 벡터DB 기반 역할 시스템을 통합한 사내 AI IDE "AI Harness"를 구축한다.

## 2. 왜 하는가

### 현재 문제
- Cursor, Kiro 등 외부 AI IDE는 프로젝트 지식이 없음 — 매번 컨텍스트를 수동 제공해야 함
- 각 도구별 설정 파일이 파편화됨 (.cursorrules, .kiro/steering 등)
- 벡터DB 기반 역할 시스템(`:명령어`)이 steering 규칙에 의존 — 도구가 바뀌면 재설정 필요

### 해결 방향
- 벡터DB 자동 참조 + 역할 시스템이 IDE에 내장된 자체 도구
- 어떤 프로바이더든 API 키만 있으면 사용 가능 (Anthropic, OpenAI, Ollama 등)
- 팀 전원이 동일한 지식 베이스와 규칙으로 작업

## 3. 기술 결정사항

| 항목 | 결정 | 근거 |
|------|------|------|
| 베이스 | 최신 VS Code (1.117) fork | void(1.99 기반)에 업스트림하는 것보다 최신에 void를 이식하는 게 현실적 |
| AI 시스템 | Void의 자체 AI 시스템 이식 | API 키 직접 입력, 18개+ 프로바이더 지원, Copilot 인증 불필요 |
| 벡터DB 연동 | Void의 AI 파이프라인에 주입 | MCP로 매 요청마다 기본 규칙 로드 + 역할 자동 감지 |
| 기존 기능 | Void의 Apply, Agent, Autocomplete 활용 | 직접 구현 대비 수개월 절약 |
| 설정 경로 | `.ai-harness/` | 브랜딩 일관성 |
| VS Code 원본 chat | 유지 (제거 안 함) | 제거 시 참조 깨질 위험, 간섭 없음 |
| 브랜치 전략 | main(업스트림 전용) + ai-harness(작업) | 업스트림 가이드 별도 문서 참조 |

## 4. 작업 범위

### Phase 1 — 기반 구축

#### 1-1. 브랜딩 변경
- `product.json` 수정 (nameShort, applicationName, dataFolderName 등)
- 아이콘 교체 (`resources/` 폴더)
- win32AppId GUID 생성

#### 1-2. Void AI 시스템 이식
- `src/vs/workbench/contrib/void/` 폴더 전체 복사
- Void가 수정한 VS Code 원본 파일 파악 및 최신 구조에 맞게 적용
  - 서비스 등록 코드 (registerSingleton)
  - Contribution point 등록
  - Electron main process IPC 채널
  - React 빌드 스크립트 (package.json)
- 의존성 추가 (`@anthropic-ai/sdk`, `openai`, `@google/genai`, `ollama` 등)
- 빌드 확인 (npm install → compile → 실행)

#### 1-3. MCP 설정 경로 변경
- `~/.void-editor/mcp.json` → `~/.ai-harness/mcp.json`
- product.json의 dataFolderName 변경으로 자동 반영

### Phase 2 — 벡터DB 연동

#### 2-1. 기본 규칙 자동 로드
- Void의 시스템 프롬프트 조립 시점에 MCP로 벡터DB 호출
- `_loadBaseRules()` 로직을 Void의 `convertToLLMMessageService.ts` 또는 `prompts.ts`에 이식
- 캐싱 (세션당 1회 로드)

#### 2-2. 역할 슬래시 커맨드
- `/ask`, `/develop`, `/review`, `/security`, `/plan`, `/onboard`, `/infinite` 7개
- Void의 채팅 UI에 슬래시 커맨드 등록
- 커맨드 선택 시 MCP로 벡터DB에서 역할 문서 로드 → 시스템 프롬프트에 주입

#### 2-3. 역할 자동 감지
- 슬래시 커맨드 없이도 사용자 메시지 분석하여 적절한 역할 자동 적용
- `_detectRoleViaMcp()` 로직 이식
- confidence가 high일 때만 적용

### Phase 3 — 안정화

#### 3-1. 빌드 파이프라인
- Windows x64 빌드 확인
- 배포용 실행 파일 생성 테스트

#### 3-2. 테스트
- API 키 입력 → Claude/OpenAI 호출 정상 동작
- MCP 서버 연결 → 벡터DB 검색 정상 동작
- 역할 슬래시 커맨드 → 역할 문서 로드 확인
- Agent 모드 → 파일 읽기/쓰기/터미널 실행 확인

## 5. Void에서 가져오는 것

### 그대로 가져오는 것
- AI 채팅 UI (React WebView 사이드바)
- LLM 메시지 파이프라인 (IPC 기반)
- 18개+ 프로바이더 SDK 연동
- Agent 모드 (도구 사용: 파일 읽기/쓰기, 터미널, 검색)
- Fast Apply / Slow Apply (코드 수정 적용)
- AI Autocomplete (코드 자동완성)
- Checkpoint 시스템 (변경사항 스냅샷/롤백)
- MCP 도구 연동
- Quick Edit (Ctrl+K 인라인 편집)

### 수정하여 가져오는 것
- 시스템 프롬프트 (`prompts.ts`) — 벡터DB 규칙/역할 주입 추가
- MCP 서비스 — 벡터DB MCP 서버 자동 연결 로직 추가
- 설정 UI — 벡터DB MCP URL 설정 항목 추가

### 가져오지 않는 것
- Void 브랜딩/아이콘
- Void 업데이트 서비스 (자체 업데이트 서버 불필요)
- Void 메트릭스/텔레메트리

## 6. 우리가 새로 만드는 것

- 벡터DB 기본 규칙 로드 (`_loadBaseRules`)
- 역할 슬래시 커맨드 7개 등록 + MCP 연동
- 역할 자동 감지 (`_detectRoleViaMcp`)
- `.ai-harness/` 경로 시스템 (skills, instructions, agents, hooks)
- 브랜딩 (아이콘, 이름, GUID)
- 하네스 MCP 서버 접속 정보 환경변수 처리

## 6-1. 하네스 MCP 서버 환경변수

소스 레벨에서 강제하는 벡터DB MCP 서버의 접속 정보는 환경변수로 주입한다.
현재는 `docs-ai.platbread.com/mcp`를 사용하지만, 다른 프로젝트에서도 사용할 수 있도록 하드코딩하지 않는다.

### 환경변수 목록

| 환경변수 | 설명 | 기본값 | 필수 |
|----------|------|--------|------|
| `AI_HARNESS_MCP_URL` | 하네스 MCP 서버 URL | `https://docs-ai.platbread.com/mcp` | N (기본값 사용) |
| `AI_HARNESS_MCP_SERVER_NAME` | MCP 서버 식별 이름 | `ai-harness-docs` | N |
| `AI_HARNESS_MCP_API_KEY` | MCP 서버 인증 키 (필요 시) | (없음) | N |

### 적용 방식
- IDE 시작 시 환경변수를 읽어 하네스 MCP 서버를 자동 등록
- 환경변수가 없으면 기본값으로 동작
- 사용자가 `~/.ai-harness/mcp.json`에 수동 설정한 경우 환경변수보다 우선
- 다른 프로젝트에 배포할 때는 환경변수만 바꾸면 됨

### 설정 예시
```bash
# Windows
set AI_HARNESS_MCP_URL=https://my-project.example.com/mcp
set AI_HARNESS_MCP_SERVER_NAME=my-project-docs

# Linux/Mac
export AI_HARNESS_MCP_URL=https://my-project.example.com/mcp
export AI_HARNESS_MCP_SERVER_NAME=my-project-docs
```

## 7. 리스크

| 리스크 | 영향 | 대응 |
|--------|------|------|
| Void 이식 시 최신 VS Code와 호환 안 되는 코드 | 빌드 실패 | 컴파일 에러 하나씩 해결, 대부분 import 경로 변경 수준 |
| Void의 React WebView가 최신 VS Code에서 동작 안 함 | UI 깨짐 | Void의 React 빌드 스크립트 확인 및 조정 |
| 업스트림 머지 시 충돌 누적 | 유지보수 비용 증가 | 월 1회 정기 동기화, 수정 파일 최소화 |
| Void 프로젝트 개발 중단 | 버그 수정 없음 | 자체 유지보수 (AI 활용) |

## 8. 일정 (예상)

|-------|------|--------|

| Phase 2 — 벡터DB 연동 | 1주 | 역할 시스템 + 기본 규칙 자동 로드 |
